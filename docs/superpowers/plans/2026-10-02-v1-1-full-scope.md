Steps use checkbox (`- [ ]`) syntax for tracking. Translation catalogues (Task 36, part of Task 37) are generated by parallel subagents; every other task runs inline.

**Goal:** Deliver the owner's 27-point request plus the five added areas (multi-user roles, translated documents and non-Latin fonts, DOCX output, e-invoicing) as eleven sub-projects (A, B, H, C, J, D, E, F, I, K, G) on `feature/v1-core-onboarding-ui-mcp`, each leaving a releasable app with a green suite.

**Architecture:** Same shape as v1.0: server components for reads, server actions for writes, a DAL that owns authorization (`requireRole`), invariants, transactions and audit, pure domain libraries under `src/lib/*`. New boundaries: `src/components/shell/*` (sidebar, drawer, user menu), `src/lib/i18n/*` + `messages/*.json` (next-intl), `src/lib/api/*` (REST v1 + OpenAPI), `src/lib/mcp/*` (MCP server), `src/lib/einvoice/*` (GST JSON, CII, UBL, Factur-X), `src/lib/documents/docx/*`, `src/lib/documents/fonts/*` (catalogue, scripts, registry). Documents keep rendering from snapshots; protected/DOCX/PDF-A3 outputs are derived `Document` versions that never replace the canonical PDF.

**Tech Stack:** as pinned in `package.json` plus, with the reason given in each adding commit: `react-easy-crop` 6.2.3 (avatar crop), `next-intl` 4.14.8 (i18n), `zod-openapi` 6.0.2 (OpenAPI from Zod 4), `@hey-api/openapi-ts` 0.99.0 (dev, SDK), `@modelcontextprotocol/sdk` 1.31.0 (MCP), `docx` 9.8.1 (DOCX), `xmlbuilder2` 4.0.3 (CII/UBL), `pdf-lib` 1.17.1 (Factur-X assembly), `fast-xml-parser` 5.11.2 (dev, XML assertions), `@fontsource/*` static packages for the 100 Latin families and the Noto script families. Exact pins only.

**Spec:** `docs/superpowers/specs/2026-10-02-v1-core-onboarding-ui-mcp-design.md` (this plan argues from it; §3-§9e are the sub-projects, §10 the confirmed decisions). Behaviour authority remains `SPEC.md`; rules `CLAUDE.md`.

## Global Constraints

- Money is `Decimal` end to end; `roundMoney(v, currency)` only where SPEC §4.6/§4.7 say; never `number` for amounts.
- Document dates are `YYYY-MM-DD` strings; instants are UTC `Date`s; "today" is `todayIn(actor.timezone)`.
- Zod at every boundary; every `Json` column has a schema in `src/lib/schemas`.
- Every DAL function takes an `Actor`; every page, action and route handler calls `requireRole(...)` / `requireApiActor(scope)`; public routes are exactly `/api/health/*`, `/verify/*`, `/i/*`, `/legal/*`, `/api/openapi.json`, `/api/auth/*`, `/onboarding` (signed-in but pre-onboarding), and `/api/mcp` + `/api/v1/*` (key-authenticated).
- Issued documents are immutable except `sentAt`, void fields, payments, credit notes, e-invoice state and derived document versions - enforced in the DAL.
- Blobs only via `src/lib/storage`; keys stored, never URLs. Encrypted fields only via `src/lib/crypto`.
- No hex literals in `src/app` / `src/components`; colours from tokens; the accent is user-selectable (`data-accent`), used only for the brand dot, the one primary button per view, focus rings and the active-nav indicator; both themes must read correctly.
- No new dependency without a reason in the commit message; exact pins; no `any`; no Redis; no external services at runtime (no GeoIP, no Google Fonts requests).
- Conventional commits on `feature/v1-core-onboarding-ui-mcp`; **never push unless the owner asks**.
- Tests: Vitest unit under `tests/unit/**`, integration under `tests/integration/**` (real Postgres at `DATABASE_URL`, skip locally when unset, fail in CI), Playwright e2e under `tests/e2e/**` (desktop `chromium` and the new `mobile` project).
- Every task ends with `pnpm lint && pnpm typecheck && pnpm format:check` clean and the named test command green; `pnpm design:lint && pnpm design:tokens --check` whenever tokens or DESIGN files change; `pnpm db:check` whenever the schema changes.

## Review Focus

1. **Role escalation through an old path** - a VIEWER posting a server action or calling an API with a key minted before their demotion must get 403, not a write (Task 12 matrix, Task 29 key-ceiling test).
2. **Share link + password brute force and token leakage** - wrong passwords must rate-limit and never reveal whether the link exists; the unprotected canonical PDF must never be served from a protected link (Task 21 tests).
3. **Non-Latin text silently rendering as boxes** - a Hindi, Arabic or Chinese line in a description must appear in the PDF text layer (Task 38 pdf-parse round-trip).
4. **e-Invoice totals drift** - the GST JSON `ValDtls` and the CII/UBL monetary totals must equal the invoice snapshot to the paisa/cent, including rounding adjustment and TDS not being subtracted (Task 40/42 reconciliation tests).
5. **Onboarding lock-out** - a user mid-onboarding must still be able to sign out, read legal pages and finish on another device; a completed user must never see the wizard again (Task 10 tests).

## Rulings recorded at planning time

- R1 One migration per sub-project where possible (`user_prefs` in Task 4 carries every `User` column A and B need) to keep the migration list short.
- R2 Sidebar state is a cookie (`okinvo.sidebar`) written client-side with `document.cookie`; no server action, because the server only needs it for the first paint.
- R3 Accent and theme are both applied by the existing inline init script (extended to `data-accent`) so there is no flash; the server action persists them after the fact.
- R4 Avatars are stored as `Asset` rows of kind `AVATAR`; `User.image` stays untouched (social providers write external URLs there which must never be hot-linked).
- R5 The onboarding wizard is one client component with three panels and autosave per panel through one server action (`saveOnboardingAction(step, formData)`); the URL stays `/onboarding`.
- R6 Roles: `requireWriter` admits OWNER and EDITOR; OWNER-only DAL functions call `requireRole(actor, "OWNER")`. `requireOwner()` keeps its name for OWNER-only pages; `requireRole(role)` is the general page/action guard.
- R7 Catalogue-to-profile tagging uses Prisma implicit many-to-many relations (`issuerProfiles`); "no tags" means "every profile".
- R8 Template `font` becomes `{ heading, body }`; the three legacy string values map on read inside `mergeTemplateConfig`, so stored snapshots never change.
- R9 Protected, DOCX and PDF/A-3 outputs are separate `Document` versions (`format` = `PDF_PROTECTED` | `DOCX` | `PDF_A3`); the canonical `PDF` row and its hash are never replaced; the byte-identity adoption rule applies only to `PDF`.
- R10 Share links use their own token (not the verification token) so revoking a share never breaks printed QR codes.
- R11 API keys are hashed (SHA-256) like verification tokens; the plain key is returned exactly once by `createApiKey`.
- R12 REST writes reuse the server actions' Zod inputs and the same DAL functions; there is no second validation path.
- R13 MCP runs stateless over Streamable HTTP in one route handler; one `McpServer` instance per request built from the key's scopes.
- R14 UI strings move to `messages/en-US.json` namespaces that mirror route groups; `en-GB` is a hand-written overlay of spelling differences over `en-US` (missing keys fall back to `en-US` at load time); the other 113 catalogues are generated and flagged `"@@generated": true`.
- R15 Legal documents (Task 26) stay English in this branch; only their chrome (titles, navigation) is translated. Recorded in the spec's limitations.
- R16 Amount in words stays English for every document locale.
- R17 CJK document fonts are whole variable TTFs fetched from `google/fonts` at a pinned commit by `scripts/vendor-fonts.mjs`; CJK bold renders regular.
- R18 e-Invoice connectors never run in CI against live endpoints; recorded fixtures only. The NIC connector ships "unverified against a live sandbox" until the owner provides credentials.
- R19 veraPDF runs through the `verapdf/cli` container; the test skips when Docker is unavailable and CI always has Docker.
- R20 Wiki.js is an opt-in Compose profile; the markdown under `docs/wiki/` is the source and renders on GitHub without it.
