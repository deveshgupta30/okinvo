# okinvo M1-M5 Implementation Plan (full v1.0 feature set)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (inline, chosen by the owner). Steps use checkbox (`- [ ]`) syntax for tracking. Pure-library tasks (1-6) may be delegated to parallel subagents; every other task runs inline.

**Goal:** Turn the M0 scaffold into the complete, usable okinvo v1.0 described in `SPEC.md` §4-§6: allow-listed sign-in, master data, immutable numbered invoices with PDF + QR verification, payments, credit notes, dashboard, email composer, CSV/XLSX/ZIP exports, three document templates with settings-level customisation, backups, hardening, release script and Kustomize manifests.

**Architecture:** Next 16 App Router with server components for reads, server actions (`src/server/actions/*`) for writes, a DAL (`src/server/dal/*`) that owns authorization, invariants, transactions and audit, and pure domain libraries (`src/lib/*`) for money, tax, numbering, totals, formatting, templates and exports. Every document renders from a locale-formatted view-model shared by the HTML live preview and the react-pdf renderer. Blobs go through a `StorageAdapter`; secrets go through `src/lib/crypto`.

**Tech Stack:** as pinned in `package.json` (Next 16.3.8, React 19.3, Prisma 7.10 + pg adapter, Better Auth 1.7.7, Zod 4.6, decimal.js 10.6, date-fns 4.4 + @date-fns/tz, @react-pdf/renderer 4.9, nodemailer 10, qrcode, sharp, file-type, exceljs, csv-stringify, archiver, pino, react-hook-form).

**Spec:** `SPEC.md` (behaviour, authoritative), `IMPLEMENTATION_PLAN_v2.md` (how), `DESIGN.md` + v2 §24 (UI), `CLAUDE.md` (rules).

## Global Constraints

- Money is `Decimal` end to end; `roundMoney(v, currency)` only at the points SPEC §4.6/§4.7 define; never `number` for amounts; never a bare `toDecimalPlaces(2)`.
- Document dates are `YYYY-MM-DD` strings at every boundary (`src/lib/dates.ts`); instants are UTC `Date`s; "today" is `todayIn(user.timezone)`.
- Zod at every boundary; every `Json` column has a schema in `src/lib/schemas`.
- Every DAL function takes an `Actor`; every server action and route handler calls `requireOwner()` / `requireOwnerApi()`; only `/api/health/*`, `/verify/*` and `/api/auth/*` are public.
- Issued documents are immutable except `sentAt`, void fields, payments and credit notes - enforced in the DAL.
- Only `allocateDocumentNumber()` assigns numbers, inside the issue transaction.
- Blobs only via `src/lib/storage`; keys stored, never URLs; served through `/api/assets` and `/api/documents`.
- Encrypted fields only via `src/lib/crypto`; redacted in audit diffs.
- No hex literals in `src/app` / `src/components` (ESLint guard); status colours from the status palette; amounts/numbers/dates in JetBrains Mono; both themes must read correctly.
- Exact dependency pins; no new dependency without a reason in the commit message; no `any`.
- Conventional commits on `feat/initial-version-okinvo`; **never push**.
- Tests: Vitest unit under `tests/unit/**`, integration under `tests/integration/**` (real Postgres at `DATABASE_URL`, skip locally when unset, fail in CI), Playwright e2e under `tests/e2e/**`.

## Review Focus

1. **Issue transaction under failure**: a render error after commit must not undo the number; a validation error before commit must leave no sequence gap. Pinned by Task 12's rollback test.
2. **Half-up rounding at the minor-unit boundary** (e.g. `0.0075 → 0.01`, JPY `82.4175 → 82`): Task 4's table.
3. **Allow-list bypass through account linking or password sign-up**: the create-user hook must reject before any row exists (Task 7 integration test).
4. **Formula injection in exports** including leading tab/CR and unicode-prefixed variants (Task 5 guard tests; Task 21 writer tests).
5. **Verification page leakage**: draft tokens, payment status, and non-issued documents must never resolve (Task 14 tests).

## Rulings recorded at planning time

- R1 `AUTH_PASSWORD_SIGNIN=true` enables Better Auth email+password (sign-up allowed only because the allow-list hook rejects everyone else). Default off. Used by e2e/CI and by owners without an IdP. Documented in `.env.example` and README.
- R2 The three templates are variants (`ledger | classic | compact`) of one shared `Preview` and one shared `Pdf` component set, not three folders - same visible result, a third of the code.
- R3 Date conversion is explicit at the DAL boundary (`toDateString`/`fromDateString`); no Prisma result extension. The archive extension injects `archivedAt: null` on `findMany/findFirst/count` for archivable models unless the caller's `where` already names `archivedAt` (pass `archivedAt: {}` to include archived).
- R4 Document fonts are vendored as WOFF files under `src/lib/documents/fonts/` (copied from `@fontsource/*` by `scripts/vendor-fonts.mjs`) so the standalone image needs no tracing tricks.
- R5 The builder's live preview runs the same pure modules (money/tax/totals) in the browser and renders the HTML `Preview`; the PDF is rendered server-side only.
- R6 UI primitives are hand-written in `src/components/ui/` in shadcn's style from the tokens; `shadcn add` is not run.
- R7 Rate limits: memory store by default; `postgres` store on `RateLimitBucket`. Limits per v2 §14.
- R8 Mailpit joins `compose.dev.yml`; the email integration test asserts through its API when `MAILPIT_URL` is set, otherwise skips.
- R9 Dashboard base-currency figures use each invoice's `fxRateToBase`; "received this FY" sums `amountApplied × fxRateToBase` of payments dated in the FY.
- R10 "Export documents" renders any missing PDF lazily through the same idempotent `ensureDocument`.
